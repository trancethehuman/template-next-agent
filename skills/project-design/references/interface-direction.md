# Interface direction

Read this for a new screen, a substantial feature, or a redesign. For a small edit, use only the relevant decision.

## Make the task visible

Identify what someone comes to inspect, compare, enter, decide, or recover. Give that object most of the useful space. A transaction workspace earns its identity through legible rows and understandable decisions; a settings screen through clear groups and consequences.

Inventory the material before designing: existing content, real data fields, actions and destinations, available assets, and missing information. Use the product's nouns in labels and headings. Keep claims and metrics grounded in supplied evidence; visibly label synthetic demonstration data.

Select the working surface by the task:

| Task | Useful starting point |
| --- | --- |
| Compare many records | Table with stable columns, clear row identity, and filters near the results. |
| Investigate a record | List or table with an adjacent detail region or an accessible detail route. |
| Follow asynchronous work | Progress summary plus per-item states and a way to inspect failures. |
| Configure a feature | Grouped fields with local help, validation, and explicit save feedback. |
| Find an example or destination | Directory with meaningful names, short descriptions, and direct links. |
| Understand a trend | Chart with units, period, provenance, and a readable data alternative. |

These are starting points. Preserve an existing successful pattern when the request does not call for replacing it.

## Hierarchy and density

Use one clear primary action per working region. Make secondary and destructive actions distinguishable by role. Keep related controls near their content; use progressive disclosure for details that would otherwise compete with the main task.

Let spacing and alignment establish groups before adding borders and containers. Repeated records need a consistent rhythm. Avoid a separate card for every value or a row of decorative statistics ahead of the content someone needs to use.

Keep labels direct, data legible, and numeric columns aligned with tabular numerals. Application headings can be compact. A long table or a complex form does not need a marketing hero, a screen word limit, or decorative sections.

Retain the existing navigation shell and destinations. Extend it when a feature needs a discoverable home. Choose conventional tabs, breadcrumbs, menus, and disclosure patterns according to the relationships between screens and tasks.

## Visual system

Read the actual tokens and installed components. Carry the current type roles, surface hierarchy, border treatment, radius, spacing, and icon family into the change. Use accent color to explain action, selection, or state; communicate status in words as well.

When the user requests a new direction, vary meaningful axes such as compact versus spacious density, inline versus adjacent detail, or quieter versus stronger emphasis. Choose from the product's needs. A new palette alone will not fix a confusing flow.

Use images when they convey information. For software, show the actual interface or a working feature when it helps. Never invent testimonials, customer logos, performance claims, or successful outcomes to fill space.

Use motion to communicate a state change or spatial relationship. Keep focus feedback immediate, avoid layout jumps and broad `transition: all`, and respect reduced motion.

## Responsive behavior

Use a small, ordinary desktop, and wide viewport to check the chosen layout; include an intermediate width when a sidebar or split view changes shape. Let grids and flex children shrink without clipping important content.

On narrow screens, prioritize the record identity, important value or decision, status, and primary row action. Deliberate horizontal scrolling can serve a wide comparison table if headings and controls remain usable. Do not simply hide the columns needed to understand a decision.

Reflow toolbars and field groups. Let long descriptions wrap and keep actions reachable. Fix overflow at its cause instead of masking it with page-wide clipping. Large screens may use more space for tables and details while keeping prose readable.
